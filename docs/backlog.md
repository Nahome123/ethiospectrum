# Prioritized backlog

Each issue below uses synthetic data only. Unless stated otherwise, all require Zod validation, server/database authorization, keyboard-accessible UI, English/Amharic/Spanish review, and unit/integration/e2e coverage.

ETH-012 is implemented locally with a migration-defined private `family-documents` bucket, 20 MiB PDF/DOCX/TXT validation, trusted UUID-backed paths, signed upload/download, household and Storage RLS, archive-only removal, translated document routes, and synthetic-data tests. It does not implement content-signature validation, malware scanning, OCR, parsing, background cleanup, or document processing. Native Amharic and Spanish review plus manual accessibility and local Storage testing remain required before release.

ETH-013 is implemented locally as a secure, metadata-only document binder with server-derived household context, validated URL state, active-dependent and household-level filters, category/MIME/status/date filters, fixed sorting, 12-row server pagination, responsive cards, a keyboard-accessible mobile filter dialog, detail/back navigation, dashboard links, and archive-aware behavior. It adds no migration, document-content search, OCR, parsing, AI, public sharing, worker, versioning, or permanent deletion. Native Amharic and Spanish review plus local accessibility/Storage testing remain required before release.

ETH-014 is implemented locally as a controlled server-side processing foundation: idempotent document jobs, bounded retries, a secret-protected worker route, private Storage revalidation, TXT/DOCX/PDF text extraction, explicit processing statuses, derivative RLS, status/retry UX, and synthetic local database/browser coverage. It adds no OCR, malware scanning, content-search UI, embeddings, AI analysis, document chat, public sharing, notifications, or permanent deletion. Native Amharic and Spanish review plus local accessibility/worker testing remain required before release.

ETH-015 adds secure, source-grounded AI document summaries for active, completed documents only. It uses a separate summary lifecycle, server-only provider boundary, controlled language selection, document-scoped source references, bounded long-document work, viewer read-only access, and a distinct worker secret. It adds no OCR, document chat, embeddings, vector search, cross-document search, public sharing, provider tool use, or professional conclusions. Local database/browser verification, native Amharic and Spanish review, and a reviewed deployment remain required; this status does not imply a hosted migration or scheduler has run.

ETH-016 adds an OCR fallback only for active uploaded PDFs that normal extraction marked `needs_ocr`. It uses a dedicated RLS-protected OCR job lifecycle, private server-side PDF rendering with bounded page/pixel/time limits, a mockable provider boundary, Unicode-preserving normalization, deterministic derivative replacement, and a separate worker secret. Successful usable OCR output transitions `needs_ocr` to `completed`; a failed or empty OCR result stays `needs_ocr` and can be retried within the bounded attempt limit. It does not add Q&A, embeddings, vector search, content-search UI, public page images, public sharing, or professional claims. Native Amharic and Spanish review plus local browser/manual verification remain required before release.

ETH-020 is implemented locally as an owner-bound citation evidence viewer for completed summaries, one-turn answers, and chat responses. It resolves only persisted same-document sources through a narrow security-definer RPC, exposes a short verified excerpt on demand, gives PDF citations an authorized private page viewer, uses logical sections for DOCX/TXT, and returns one unavailable state for stale, invalid, archived, removed, or cross-household sources. It revokes browser page/chunk enumeration and adds aligned English/Amharic/Spanish controls plus synthetic local coverage. It does not add source search, export, sharing, provider work, cross-document retrieval, moderation, or a new authority layer. Native Amharic and Spanish review plus a reviewed non-production rollout remain required.

ETH-021 is implemented locally as a household-authorized roadmap and action-item workflow. Active owner, administrator, member, and viewer access follows the household permission matrix; only owners and administrators archive, restore, or manually reorder. The additive schema supports title, optional description, category, priority, controlled status transitions, calendar due date, optional active dependent, optional household assignment, server-owned completion state, archive state, ordering, stale-write checks, and idempotent creation. It does not schedule or send reminders, mutate the existing reminder groundwork, create worker/provider work, or perform a hosted migration. Native Amharic and Spanish review plus a reviewed non-production rollout remain required.

ETH-027 is implemented locally as request-level appointment scheduling. The assigned specialist proposes one timezone-aware appointment for an open, assigned request, and the household consents explicitly through a versioned, unchecked acknowledgment. The dormant `appointments` table is reused with its unsafe `can_access_household()` policy replaced by request-scoped forced RLS. Nonexistent and ambiguous daylight-saving local times are rejected, durations are limited to 30/45/60 minutes, proposals must fall between 24 hours and 90 days out, overlapping appointments for the same specialist or household are refused using half-open intervals, and only one live appointment exists per request. Rescheduling cancels and supersedes rather than editing in place, and assignment revocation or request closure cancels any live appointment atomically with an immutable audit trail. It adds no notifications, recurrence, availability calendars, external calendar integration, in-person meetings, or ETH-028 billing. Native Amharic and Spanish review remains required before release.

ETH-026 is implemented locally as request-level specialist assignment. A platform administrator assigns one eligible specialist to one open support request through the existing `support_threads.specialist_id` column plus server-controlled assignment metadata and an optimistic assignment version, and may revoke it; closing or cancelling a request revokes automatically. An actively assigned specialist reads only that request and its messages and may add immutable specialist responses, while household membership, dependents, documents, roadmap items, reminders, other requests, and assignment history stay unreachable. Revocation removes access immediately because RLS re-derives it from live database state. `household_specialists` remains dormant and `can_access_household()` is deliberately not the boundary. An append-only administrator-only audit table records assignment and revocation with controlled reasons. It adds no reactivation state, expiry, workload cap, notifications, or ETH-027 appointment behavior. Native Amharic and Spanish review remains required before release.

ETH-025 is implemented locally as a household-shared specialist support request workflow that reuses and extends the dormant `support_threads`/`support_messages` tables plus a new immutable audit table. It includes server-enforced non-emergency and household-visibility acknowledgment with a controlled copy version, bounded subject/description/message validation, an allowlisted category and preferred language, append-only messages, an open/closed/cancelled lifecycle with requester/owner/administrator authority and optimistic concurrency, five-open-request and 50-message caps, idempotent creation, read-only platform-administrator triage, and full specialist denial (including dormant active assignments). It adds no specialist assignment or response (ETH-026), attachments, dependent/document/roadmap/reminder linkage, notifications, emergency handling, guarantees, or environment variables. Native Amharic and Spanish review remains required before release.

ETH-039 is implemented locally as a protected bilingual RBT Errorless Teaching resource with direct section routes, keyboard-operable flashcards, glossary filtering, responsive source-faithful rendering, user-only reading progress, and synthetic local database/browser coverage. It preserves the provided source content and attribution but does not claim certification, provide clinical advice, replace official RBT/BACB requirements, assess competency, or store scores. Source licensing/attribution and native Amharic/Spanish content review remain required before release.
